PHASE 4 — OPEN OPENCVMANAGER
================================================================================

Analysis of src/services/OpenCVManager.js:

1. How opencv.js is imported:
   Static import at top of file (line 1):
   import opencvModule from '@techstark/opencv-js';

2. Whether import is static or dynamic:
   Static import.

3. Exact initialization sequence:
   - initialize() checks if state is READY (returns cv) or LOADING/FAILED (returns initializationPromise).
   - Sets this.state = OPEN_CV_STATES.LOADING ('loading').
   - Logs '[DIAG] OpenCV initialization started' and notifies listeners.
   - Starts async IIFE:
       Logs '[DIAG] OpenCV module loaded'
       runtimeSource = opencvModule.default ?? opencvModule.cv ?? opencvModule
       runtime = await this._waitForRuntime(runtimeSource)   <-- STALLS HERE
       verifies runtime.Mat is a function
       creates and deletes test Mat: new runtime.Mat()
       this.cv = runtime; this.state = OPEN_CV_STATES.READY;
       Logs '[DIAG] cv.Mat verified', '[DIAG] OpenCV runtime ready', '[DIAG] OpenCV initialization ready'
       notifies listeners; returns this.cv.

4. Whether it waits for cv.onRuntimeInitialized:
   In _waitForRuntime(runtimeSource):
   - Branch 1: `if (runtimeSource && typeof runtimeSource.Mat === 'function')`
     -> Evaluates to FALSE on load because runtimeSource.Mat is undefined prior to WASM compilation.
   - Branch 2: `if (runtimeSource && typeof runtimeSource.then === 'function')`
     -> Evaluates to TRUE because the Emscripten Module object defines a `then` function!
   Therefore, it never reaches the explicit onRuntimeInitialized hook in Branch 1.

5. Whether it waits for a Promise:
   YES. It returns:
   Promise.race([
     Promise.resolve(runtimeSource),
     new Promise((_, reject) => setTimeout(..., 15000))
   ]);

6. Whether that Promise has resolve():
   YES: Promise.resolve(runtimeSource).

7. Whether that Promise has reject():
   YES: the 15-second timeout rejects with an error.

8. Whether there is a timeout:
   YES: OPEN_CV_TIMEOUT_MS = 15000 (15 seconds).

9. Whether cv actually becomes available:
   Underlying WebAssembly finishes compiling, but the Promise never resolves due to
   the thenable assimilation deadlock.

10. Whether cv.Mat, cv.ORB, cv.imread, etc. are available:
    They exist on the compiled Emscripten Module, but openCVManager.cv is never set.

11. Whether initialization can remain permanently pending:
    YES. THIS IS THE ROOT CAUSE:
    - `runtimeSource` is the Emscripten Module object.
    - Emscripten defines `Module.then` as:
        function(func) {
          if (calledRun) { func(Module); }
          else {
            var old = Module["onRuntimeInitialized"];
            Module["onRuntimeInitialized"] = function() { if (old) old(); func(Module); };
          }
          return Module;
        }
    - When JavaScript executes `Promise.resolve(runtimeSource)`:
      ECMAScript standard (§27.2.1.3.2) states that resolving a Promise with a thenable
      must call `thenable.then(resolve)`.
    - When WebAssembly finishes loading, `onRuntimeInitialized` calls `func(Module)`.
    - This attempts to fulfill the Promise with `Module`.
    - Because `Module` has a `.then` property, the V8 Promise implementation treats the
      resolution value as another thenable and enqueues a new `PromiseResolveThenableJob`!
    - In the subsequent job, `calledRun` is now true, so `Module.then` synchronously calls
      `func(Module)` again.
    - V8 sees `Module` again, sees `.then` again, and re-enqueues `PromiseResolveThenableJob`.
    - Result: An infinite Promise assimilation recursion in the V8 microtask queue.
      The Promise never fulfills to a settled value.

12. Whether initialization can throw an exception:
    Syntactically yes, but execution is stuck in the microtask recursion before reaching any throw.

13. Whether the exception is swallowed:
    In OpenCVManager.js, errors are caught, logged via console.error, and re-thrown.
    In App.jsx, the re-thrown error is swallowed by `.catch(() => {})`.

14. Whether initialization blocks the renderer/main thread:
    The microtask recursion starves pending asynchronous workflows and prevents
    the 15-second setTimeout macrotask from rejecting the Promise.

   NO. The event loop is responsive; React renders, timers execute, and click handlers run.

9. What is the FIRST confirmed failure in the chain?
   - Failure 1 (OpenCV): Calling `Promise.resolve(runtimeSource)` on Emscripten's thenable Module.
